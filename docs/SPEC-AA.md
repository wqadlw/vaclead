# SPEC-AA · 抢跑轮：联系人覆盖冲刺 + 招标中提权 + 订阅提速（Agent B 认领）

> 立项：2026-11-03 W45 · 数据实证（2028 企业仅 24 家有可拨电话=1.2%；信号池 78% 是
> 已成交旧闻）+ 第三次头部调研强验证（剑鱼实时推送/拟建项目=核心付费点）。
> 命题：**"早 + 打得通"**——拓客护城河的两大支柱。

## AA1 联系人覆盖冲刺（回填任务升级）

- **每日限额 30 → 300**（详情页 1s 限速，300 页约 8 分钟；ccgp 限流守卫仍在）
- **查询升级三处**：
  1. 跳过"已有可拨联系电话联系人"的企业（不再重复抓同一公告浪费限额——旧逻辑
     只要 id 靠前就重复 fetch）
  2. **优先级排序**：招标中的企业（有 type=tender 信号）排最前——他们此刻正在
     对接采购，电话最活
  3. 排序键：(有招标中信号 DESC, id ASC)
- 边界如实记录：ggzy 中标方电话不可得（API 不给、中标详情页无 URL 可抓）——
  其法人已有（W38），电话属商业源采购范围

## AA2 招标中信号提权（行动窗口可视化）

- bulletin 端点加 `competitor` 参数（竞对动态筛选，Y1 顺带）
- 标讯中心快捷筛选加「**招标中·行动窗口**」chip（type=tender——采购正在发生）；
  行内类型徽章对 tender 用行动色强化
- 竞对动态：chip「竞对中标」（competitor=1 & type=tender_win）——对标剑鱼竞对监测
  （数据已在库，零成本）

## AA3 订阅推送提速（日批 → 两小时级）

- `_register_cron` hour 参数扩 int|str（APScheduler 原生支持 "*/2"）
- subscription_rules 从每日 04:06 → **每 2 小时**（h6：*/2:06）——日间手动扫描/
  拟建通道（未来）来的信号一小时内触达订阅者
- 边界如实：信号本体仍靠 03:30 日批采集，实时推送需 intraday 采集（ccgp 限流
  敏感，随拟建通道 P2 一起设计）

## AA4 拟建项目通道预研（只探测不实施）

- 结论记 DATA_ACQUISITION §4.3（可达 → P1 立项新通道；不可达 → 归档）
