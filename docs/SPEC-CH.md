# SPEC-CH · 通话驾驶舱轮：销售核心循环的一屏闭环（Agent B 认领）

> 立项：2026-11-07 晚 · 用户第二次说"不好用，想想为谁服务"。上一轮
> 改了信息架构（CG），这次对准**销售核心循环本身**：打谁 → 打电话 →
> 知道说什么 → 记结果 → 跟进有上下文。现状的断点：
> ①打开联系人只有一行卡片，打电话前要自己到处找"这家是谁/最近发生
> 了什么/我该说什么"——信息散在四个页签；②打完的结果标记在列表行
> 里，跟进一步要跳去线索看板；③"今日推荐"不区分"我今天主推哪条
> 产品线"。

## CH1 GET /api/contacts/{cid}/prep（通话准备聚合端点）

- contact 全量 + 企业简档 + 最近 3 条信号（证据句）+ 工艺适配
  （复用 recommend._product_match）+ 线索状态（若有：status/下一步/
  最近跟进一条）
- 一屏"为什么现在打 + 怎么聊"的原料，零跳转

## CH2 通话驾驶舱 SideSheet（联系人中心行点击）

- 三段式：**为什么现在打**（信号证据句时间线）/ **怎么聊**（产品
  适配一句销售语言 + 企业档案行）/ **动作区**
- 动作区一排完成全循环：大号「拨打」(tel:) → 7 态快标 → 已在管则
  「写跟进」一句话（POST /leads/{id}/followups）→ 未在管则「转线索」
- 打完即走，全程不离开当前页

## CH3 推荐产品线过滤

- score_candidates(product=None)：产品名 → 应用面行业集过滤；
  GET /recommendations?product=EVS
- 工作台「今日推荐」头部产品 chips（全部/EVS/干式/压缩机/鼓风机）

## CH4 拟建列表按单位聚合

- 同一单位多条公示（审批节点流）合并一行显示「共 N 条公示」——
  消除销售看到的"同一家重复三行"噪音

## CH5 词表校准第四次（数据信任）

- 实证：铜陵市食品药品检验中心被 food 的"食品"词命中（检验机构≠
  食品加工买家，语义应为检验检测）；根因=检验检测类目排在食品之后
- 修法：检验检测类目前置 + 补「检验中心」词；真库 diff 验证后重算
  受影响企业（W41 闭环模式）

## 测试

- prep 端点字段/信号证据/product 匹配；score_candidates product 过滤；
  词表 diff 方向抽验；E2E prep 侧板流程

## 边界

- prep 是聚合只读；跟进提交复用既有 lead 端点（权限语义不变）
- 未在管企业写跟进引导先转线索（撞单保护不绕过）
