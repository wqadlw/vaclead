## 二、企业级差距分析（诚实清单）

| # | 差距 | 影响 | 级别 |
|---|---|---|---|
| G1 | **采集任务无前端入口**：ggzy-harvest/ccgp-scan 只能 curl 发起，不可视、不可观测 | 运营不可用 | P0 |

| G9 | 单文件 SQLite 无备份策略 | 数据安全 | P1 |

## 三、升级路线（四阶段， acceptance 驱动）

### Phase A 采集规模化与可视化（本轮立即执行）
- **A1 采集中心**：任务页新增"官方数据采集"区块——ggzy 中标采集 / ccgp 政采扫描两张任务卡（关键词多选、天数、页数），复用 SSE 进度流与取消
- **A2 来源可视化**：企业表格加来源徽章列 + 筛选；信号列表区分 公告(tender)/中标(tender_win)/采购(tender_buy)
- **A3 全量采集**：34 强词分批（每批 ≤12 词）顺序跑双主干；完成后企业库预期 1000+ 主体、信号 1000+
- **A4 工作台数据真实性**：KPI 与信号流已接真实数据，补"来源分布"卡
- **验收**：浏览器发起全量采集→SSE 看进度→企业列表按来源筛选→信号带类型徽章

### Phase B 数据质量（✅ 2026-10-25 完成，契约 docs/SPEC-B.md，日志 docs/WORKLOG.md W2）
- B1 归一升级：uscc 精确键优先 + 名称标准化二级 + 相似度阈值三级，低置信落"复核队列"（splink 思路，SQLite 可实现）
- B2 工商补全：china-check MCP 批量补 uscc 企业的注册资本/行业/经营范围 → ICP 评分解锁（G5）
- B3 每日增量：APScheduler 定时（凌晨）跑"近 N 天"增量 + 水位表；SQLite 每日备份保留 7 份（G9）
- **验收**：同名异写企业合并率 >80%；官方企业 ICP 评分非零率 >60%；连续 3 天自动增量有新信号
- **完成情况**：①归一四级（uscc>精确名>别名+uscc回填>rapidfuzz）+80-89 复核队列（不静默）②canonical_name 保留括号地区（修复跨城市误并）③复核 API+设置页"数据复核"标签④中标画像 EnterpriseStat（82 家已有画像）⑤工商 Provider 协议（china-check 实测需 token，待配置）⑥每日 03:30 增量/04:00 画像/04:10 备份（滚动 7 份）+sync_watermark 水位⑦审计修复 7 项（POI NameError/双重 resolve/去重口径/Meili 静默吞等）。测试 126 全绿。ICP 评分解锁依赖工商凭证配置（P2 待用户注册）

### Phase C 情报深化（P2 按契约执行）
- C1 招聘信号：CDP 持久 profile 采集 Boss直聘岗位 → signal(type=hiring)，"在招真空设备工程师"=扩张意图
- C2 浏览器采集池：crawl4ai/裸 Playwright 管理 ggzy.gov.cn 公告侧（招标公告早期信号，补中标数据的滞后）
- C3 军队采购试探：weain.mil.cn 注册与采集评估
- **验收**：三类信号源在时间线上可叠加判断单一企业意图

### Phase D 触达闭环（契约已就绪）
- D1 GLM 接入：按 docs/LLM_PROMPTS.md 契约开 LLM 后端（信号解析/资格判断），llm_calls 计费可观测
- D2 邮件管道：warmup.py 已就位，5 表 schema 落地
- D3 企微：按 docs/WEWORK_INTEGRATION.md 填空
- **验收**：线索→触达→回复→跟进 全链路演示

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 官方接口限流/风控升级 | 限速保守（ggzy 1.5s / ccgp 3-6s）、批次小步、失败退避；通道有多元冗余（CSV/商业API兜底） |
| 抽取质量长尾 | 已修复两大类误抽；复核队列（B1）承接低置信数据，不静默丢弃 |
| 名称归一误合并 | 三级匹配置信度，低置信必须人工确认后才合并 |
| SQLite 规模上限 | 10万级企业无压力（WAL+FTS5+Meili 投影）；真到百万级迁 Postgres 的 ORM 兼容已预留 |
| 合规红线 | 只采官方公开数据、固定 UA、不绕验证码、不碰登录后商业产品；全部存储可溯源 |
